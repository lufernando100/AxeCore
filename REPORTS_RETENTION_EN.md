# Accessibility reports retention and cleanup

Recommendations for storing and cleaning up reports generated by the accessibility auditing tool (axe-core).

1. Suggested policy
   - Keep aggregated reports (HTML) for at least 90 days.
   - Keep full JSONs and screenshots for 30 days by default.
   - Keep reports associated with releases or critical incidents indefinitely (archive).

2. Storage
   - In CI: upload artifacts with `actions/upload-artifact` (retention configurable).
   - For long-term: upload to S3 / Azure Blob and apply lifecycle policies (transition to cold storage after 90 days, delete after 365 days, according to policy).

3. Automation
   - A local/server script `scripts/cleanup-reports.ps1` can remove files in `reports/` older than N days.
   - Integrate periodic cleanup using GitHub Actions or a scheduled task (Task Scheduler / cron).

4. Security and privacy
   - Sanitize PII, cookies and tokens before persisting.
   - Control access to storage buckets/artifacts.

5. Best practices
   - Do not version reports in git.
   - Add metadata to each report: timestamp, runId, gitSha, browser.
   - Compress old JSONs to save space.

Quick example usage of the script:

```powershell
# Run cleanup for 90 days
pwsh ./scripts/cleanup-reports.ps1 -Days 90 -ReportsPath .\reports
```
